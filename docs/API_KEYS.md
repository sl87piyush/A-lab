# Private backend, credentials and deployment

## Server-only values

Set these in `services/api/.env` for local development, or your HTTPS host's environment settings. A private local `.env` has already been created with generated ATTEMPLY_SETUP_CODE and SESSION_SECRET (permissions 0600). Enter only your Mistral key there; do not overwrite this file with the example or share its contents. The `.env.example` still contains placeholders only:

| Variable | Purpose |
| --- | --- |
| MISTRAL_API_KEY | Mistral account credential; server only |
| MISTRAL_OCR_MODEL | Defaults to `mistral-ocr-4-1` |
| MISTRAL_ANALYSIS_MODEL | Defaults to `mistral-small-latest` |
| ATTEMPLY_SETUP_CODE | Private device pairing code |
| SESSION_SECRET | Long random JWT signing secret, required in production |
| PORT | Host-provided listening port, default 3001 locally |
| DATA_DIR | Private job/source storage directory |
| MAX_UPLOAD_MB | Default 25 |
| MAX_SELECTED_PAGES | Default 20 |
| PDFTOPPM_BIN | Optional explicit Poppler executable path |

Only `EXPO_PUBLIC_API_BASE_URL` is public and belongs in the Expo preview environment or `apps/mobile/.env`. It is an HTTPS URL, never a Mistral key. The app also supports entering this URL during pairing. Environment example files contain placeholders only.

Models are checked using the account's `/models` list before actual OCR. Model availability is account-specific; no model availability was claimed without a credentialed call. Text-model absence falls back to deterministic observations. OCR failures remain failures.

## Pairing and privacy

POST `/v1/auth/pair` accepts a setup code and UUID device ID. The code is compared using SHA-256 plus timing-safe comparison. Pairing is rate-limited to 5 requests/minute/IP. A signed token expires in 24 hours. Upload, job, debug and analysis endpoints require this token. Source/job reads check device ownership, even when a different device has its own valid token. Production startup refuses missing pairing/session settings.

Rotate SESSION_SECRET to invalidate sessions, and ATTEMPLY_SETUP_CODE to stop reuse of the old pairing code. Existing session expiry remains enforced. Pairing is private prototype access, not a user-account service.

Uploaded originals and raw OCR are private on the API disk. Failed temporary preparations are removed; completed sources are retained for short-term retry/debug and cleaned at startup and every ten minutes while the queue is idle. Device sources remain until deletion. **Delete my server imports** and **Delete local data** are separate explicit actions in Settings. Deleting local data does not revoke the SecureStore pairing credential.

## HTTPS deployment using Render (free testing plan)

`render.yaml` explicitly selects `plan: free`, with no persistent disk. `DATA_DIR=/tmp/attemply` is temporary. This avoids the paid-instance/disk requirement in the previous blueprint. Render's Free plan is for testing: idle services sleep after 15 minutes, cold startup can take about a minute, and server uploads/job files disappear on restart, redeploy or sleep. Completed tests/history and retained originals are stored separately on the phone. After a server source expires, use **Prepare source again** before OCR. Mistral account credits/usage are separate from hosting.

`services/api/Dockerfile` installs Node and Poppler, compiles the API and starts the correct output. Host PORT is respected; `/health` is the health check. SIGTERM/SIGINT shut down the server and await active processing.

1. Use the updated `main` branch in the private GitHub repository. `.gitignore` and `.dockerignore` exclude local credentials, private files and build outputs.
2. Start a new Blueprint creation from `render.yaml`, or reload the existing unsubmitted creation flow so it reads the latest commit. Verify it shows **Free** and no disk before deploying. If a stale Blueprint form continues to request payment, use the manual Web Service flow below. Account-specific restrictions can still prevent free deployment; no cardless account acceptance is claimed until Render accepts it.
3. Enter MISTRAL_API_KEY and ATTEMPLY_SETUP_CODE when prompted. SESSION_SECRET is generated by the blueprint. Supply secrets only in Render's environment settings, never in Git.
4. Wait for deployment to show Live. Open `https://YOUR_API.onrender.com/health` in a browser and wait for a JSON response before pairing; a cold server can take longer than the app's pairing timeout. `ok: true` and `ocrConfigured: true` verify startup/key configuration, not a successful OCR call.
5. In the installed app, enter the base HTTPS URL without `/health` and the same ATTEMPLY_SETUP_CODE under **Connection & local data**, then **Pair this device**. Import one clear photo and a small page selection first. The app stores the entered URL, so the existing APK can use the new host.

### Manual Free Web Service fallback

In Render choose **New > Web Service**, connect the GitHub repository, and use:

| Field | Value |
| --- | --- |
| Branch | `main` |
| Root directory | Leave empty (repository root) |
| Runtime / Language | Docker |
| Dockerfile path | `./services/api/Dockerfile` |
| Docker build context | `.` |
| Instance type | **Free** |
| Health check path | `/health` |
| Persistent disk | None |

Add these environment variables before creating the service:

- MISTRAL_API_KEY: your actual Mistral key.
- ATTEMPLY_SETUP_CODE: the private code from your local `.env`.
- SESSION_SECRET: the generated long random secret from your local `.env` (manual creation does not use Blueprint secret generation).
- MISTRAL_OCR_MODEL: `mistral-ocr-4-1`.
- MISTRAL_ANALYSIS_MODEL: `mistral-small-latest`.
- DATA_DIR: `/tmp/attemply`.

Leave PORT to Render. The Dockerfile supplies the start command. Do not attach a disk or select paid compute. If account verification still requires a payment method with **Free** selected, stop: this repository cannot override Render's account policy.

For durable server job/source storage later, choose an explicitly paid instance, attach a persistent disk at `/var/data`, and set DATA_DIR to `/var/data/attemply`. Only files under the mounted disk survive. The free default deliberately provides no durable server-storage guarantee.

Official references: [Free plan limits](https://render.com/docs/free), [Blueprint configuration](https://render.com/docs/blueprint-spec), [Web service creation](https://render.com/docs/web-services).

No deployed API URL is claimed until deployment succeeds. Docker is not installed in the local execution environment, so the Docker image still requires a successful Render/CI build.

## Troubleshooting

- 401 from private API: re-pair; check SESSION_SECRET consistency across replicas.
- Pairing 503: configure ATTEMPLY_SETUP_CODE.
- OCR key rejected: update server MISTRAL_API_KEY and check account/billing.
- Configured model unavailable: choose a model returned by the account's list; do not silently swap OCR models.
- 413: split the source below the upload/expanded-ZIP limit.
- 429: wait; expensive jobs use one processing slot and a bounded queue.
- PDF preview unavailable: ensure Poppler is installed and unencrypted PDF input is valid.
- Never paste secrets into logs, source, diagnostic exports or the mobile build.
