# Attemply Lab 1.0.1 — native upload correction

## Reproduced cause

Expo SDK 58's multipart encoder rejects a React Native URI-only FormData part (`{ uri, name, type }`) with `Unsupported FormDataPart implementation`. The app used this representation in both source uploads and developer JSON/ZIP imports. The failure occurs in the client before the upload reaches the backend; it does not indicate a corrupt PDF.

Both paths now use an `expo-file-system` File as the multipart part and explicitly use `expo/fetch`. Multipart Content-Type/boundary remains generated by the network implementation. Android versionCode is 2, version 1.0.1; the package ID and signing key are retained for in-place installation.

- 60 core/API/SQL tests pass; 3 credential/private-fixture tests remain skipped.
- Strict TypeScript and ESLint pass.
- The supplied PDF is valid, unencrypted, 3 pages and 539,422 bytes. It remains outside the repository.

## Install the fix

Transfer the new APK to the Android phone and choose Install/Update over the existing app. Open the retained PDF source and choose **Prepare source & page previews**. Re-pair only if the session has expired. Uploads/previews do not call Mistral OCR; **Extract selected pages** does. If the next step reports Mistral 429, review the account's Document OCR allowance on its Limits page; successful `/health` or `/models` access does not prove OCR quota is available. [Mistral usage and limits](https://docs.mistral.ai/admin/billing-usage/usage-limits).

Official SDK guidance: [Expo 58 FileSystem file uploads](https://docs.expo.dev/versions/v58.0.0/sdk/filesystem/).
